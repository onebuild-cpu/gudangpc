## PASSED CHECKS

- **Check 4** — all dashboard routes map to methods that call the proper access guard first.
- **Check 5** — every POST handler validates CSRF; every `<form method="POST">` includes the hidden CSRF input (42/42 matched).
- **Check 6** — no user input concatenated into SQL. All dynamic identifiers are whitelisted/regex-validated; values use prepared statements with emulated prepares disabled in `config/database.php:16`.
- **Check 8 (upload validation part)** — `Controller::processAndSaveImage()` uses `finfo` MIME allowlist, 2 MB size limit, GD re-encode and a random name; CSV import uses a 5 MB limit, `.csv` extension check, NUL-byte check, `finfo` MIME allowlist and a random filename in `storage/`. Only the `.htaccess` sub-check produced F-002.
- **Check 9 (redirect behaviour)** — `/go/<offer_id>` reads the offer by integer id from the DB and rejects any URL not starting `http(s)://`; it cannot redirect to an arbitrary host not stored in the DB. Click logging hashes the IP and binds values via a prepared statement. The salt caveat is F-003.
- **Check 11 (role enforcement)** — settings, admin management and member activation are root-only in the controllers; no admin bypass found. The sidebar link issue is F-005.
- **Check 12 (active-offer usage)** — every public visibility query uses `OfferModel::activeCondition()`; no page-level copies found. The unused `countStale()` duplication is F-008.
- **Check 13 (HAVING logic)** — the two `HAVING product_count > 0` clauses use a correlated scalar subquery (no aggregate in the outer SELECT), so `ONLY_FULL_GROUP_BY` does not invalidate them; `COUNT(DISTINCT p.id)` is correct given the unique `(product_id, vendor_id)` rule.
- **Check 14 (partial)** — category, product, seller, `/locations` and search pages have no query-inside-loop. Homepage is the exception (F-006).
- **Check 17 (partial)** — the whole-project `check_rules.php` run passed; no `onclick=`/`onsubmit=` handlers found in views. Missing docblocks are F-016.
- **Check 19 (dashboard side)** — no Indonesian user-facing text found in dashboard views.

## NOT CHECKED

- **MySQL/MariaDB server version** — the task forbids running SQL and no version is pinned in config, so the live compatibility of `HAVING` was reasoned from SQL semantics, not verified against the server.
- **Actual deployment environment** — `APP_ENV`, vhost document root and PHP SAPI (Apache module vs PHP-FPM) cannot be verified from files alone; `.env` exposure and `.htaccess` effectiveness depend on them.
- **Runtime/browser behaviour** — CSP enforcement, rendered layout, and client-side JS were not executed.
- **Live database contents** — no SQL was run; row counts, actual image paths and real duplicate data were not inspected.
- **External use of `bin/` scripts** — POs may invoke seed/placeholder scripts outside the repo; only in-repo references were checked.
- **Full docblock audit** — only a spot-check of controllers/models was done; F-016 lists what that spot-check found.
