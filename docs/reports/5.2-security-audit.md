## PASSED CHECKS

- **Check 2 (login flows)** — `session_regenerate_id(true)` is called on staff login (`AuthController.php:269`), member login (`:202`), Google sign-in (`SocialAuthController.php:283`) and Facebook sign-in (`:156`), each with `CsrfProtection::invalidateToken()`.
- **Check 3** — `AuthController::logout` (`AuthController.php:286-328`) requires POST and valid CSRF, clears `$_SESSION`, expires the cookie, destroys the session, starts a fresh one, regenerates the id and invalidates the CSRF token. Both UI logout controls are POST forms with hidden CSRF (`views/layouts/navbar.php:203-204`, `views/dashboard/_sidebar.php:184-185`).
- **Check 4 (throttling mechanism)** — `RateLimiter.php:22-29` limits login (5/300s), register (3/3600s), password_reset (3/3600s), api (60/60s), admin_write (30/60s), ai_search (20/60s). Staff login is keyed by phone (`AuthController.php:230`), member login by email (`:172`), registration by `REMOTE_ADDR` (`:64`), so `X-Forwarded-For` cannot bypass them (the forwarded-header branch in `RateLimiter.php:185-189` is commented out). No password-reset flow exists, so that limit is unused (N/A, not a finding).
- **Check 5 (hashing/comparison/logging)** — Argon2id via `password_hash(..., PASSWORD_ARGON2ID)` in `UserModel.php:11-16,71`, `MemberModel.php:15-21,36`, `bin/add_root.php:110`, `bin/change_pwd.php:13`. Dummy-hash `password_verify` for missing users (`UserModel.php:89-105`, `MemberModel.php:73-79`), `hash_equals` for CSRF and OAuth state. No plaintext password logging found. Policy inconsistency is S-003.
- **Check 6 (login messages)** — `"Invalid email or password."` (`AuthController.php:209`) and `"Invalid phone number or password."` (`:281`) do not reveal account existence. Registration enumeration is S-004.
- **Check 8 (headers present)** — `X-Content-Type-Options: nosniff` (`FrameworkHeader.php:144`), `X-Frame-Options: DENY` (`:145`), `Referrer-Policy: strict-origin-when-cross-origin` (`:146`), HSTS only on HTTPS (`:156-157`), CSP (`:251`), plus Permissions-Policy, COOP on HTTPS and empty X-Powered-By. CSP reporting/config issues are S-002/S-006/S-008.
- **Check 9** — Google sign-in state is random (`SocialAuthController.php:313-314`), checked with `hash_equals` and made single-use (`:337-351`); redirect URI is built from APP_URL (`:166-173,299,369`); cURL peer/verification TLS verification and 5s/10s timeouts are set (`:60-63,187-190`); unverified email is rejected (`:407-416`). No OIDC nonce is used because the userinfo endpoint is used, not an ID token.
- **Check 10** — every dashboard state-changing route maps to a controller method with a `REQUEST_METHOD !== 'POST'` guard before CSRF (full mapping verified across `AdminSearchController`, `AdminUserController`, `MemberController`, category/brand/store/vendor/location/product/import/settings controllers).

- **Check 12** — CSV import stores uploads under `storage/` with a generated name `import_<random>.csv` (`AdminProductImportController.php:185-186`); the original filename is only used in messages and extension checks; `unlink` targets only generated paths (`:72-74,213-225`); `fgetcsv` + prepared statements only; no shell/include/eval.
