**Commit:** `f2135af Add frosted image hero image`

### What was added

A frosted-glass overlay on the **active parallax image layer only**, at `frontend.css:108-119`:

```css
.layer-1::after {
    content: '';
    position: absolute;
    inset: 0;
    z-index: 1;
    pointer-events: none;
    background: rgba(255, 255, 255, 0.14);

```

### Decisions

- Style: frosted overlay **over** the image, using `backdrop-filter` so the artwork itself appears blurred/frosted.
- Scope: only the active layer-1 image. Layers 2 and 3 remain commented out in `views/home/index.php`.
- The text layer (`.brand-container`: "GudangPC" and "Banyak Toko, Satu Gudang! / Cari Harga Lebih Murah, Nggak Pakai Ribet.") is a sibling with `z-index: 3` and receives **no** blur or tint.
- A CSS pseudo-element was used instead of new markup because the hero script shows the image-error fallback via `img.nextElementSibling`; inserting a div between the `<img>` and `.parallax-fallback` would break that logic.
- No inline styles, no JS edits, no new files or libraries.

### Verification

- Desktop and mobile hero views: image looks frosted, text stays sharp (user-approved).
- Parallax scroll still moves only the image layer (user-approved).

## 2. Image placeholder scripts

**Commit:** `fc915bf Fixing image placeholder with php scripts`

All scripts live in `bin/` and require PHP GD + WebP, `public/assets/fonts/Poppins-Bold.ttf`, and the DB settings in `.env`. On this machine use `C:\xampp\php\php.exe` (plain `php` is not on PATH).

### Scripts

| Script | What it does |
|---|---|
| `bin/create_category_placeholder.php [slug]` | Draws an 800×800 WebP with the category name, saves it to `public/uploads/categories/placeholder-<slug>.webp`, and writes `/uploads/categories/<file>` into `categories.image` only when empty. Default slug: `gaming`. Never overwrites. |
| `bin/fill_product_images_from_categories.php` | One-time DB update: for every category with an image, sets `products.image` to that category image where the product image is NULL/empty. Never overwrites. |
| `bin/create_store_placeholder.php [slug]` | Draws a store logo placeholder, saves it to `public/uploads/stores/placeholder-<slug>.webp`, and writes it to `stores.logo`. With no argument it fills **all** stores missing a logo; with a slug, only that store. |
| `bin/create_vendor_placeholder.php [slug]` | Same pattern for vendors: `public/uploads/vendors/placeholder-<slug>.webp` → `vendors.image`. With no argument it fills all vendors missing an image. Requires migration 025. |

Pre-existing, not part of this work: `bin/seed_images.php` generates *product* placeholders in `public/uploads/products/` for ten fixed slugs; it does not create category/store/vendor logos.

### Schema addition

`database/migrations/025_vendors_image.sql` adds the nullable column the vendor script needs:

```sql
-- Migration 025: add an optional image path for vendors.
ALTER TABLE `vendors`
  ADD COLUMN `image` varchar(255) DEFAULT NULL AFTER `description`;
```

The worker did **not** apply this migration; it must be applied locally before `create_vendor_placeholder.php` is used.

### Documentation

`docs/CATEGORY_PLACEHOLDER_HOWTO.md` is the how-to guide. It covers:

- where each image is displayed (category pages vs product cards vs dashboard store list),
- exact PowerShell commands for one slug or all missing rows,
- expected output, re-run safety, and the one-time nature of the DB updates,
- the `monitors` vs `monitor` slug distinction,
- separate sections for stores and vendors.

### What was actually run

- `create_category_placeholder.php gaming` → created `placeholder-gaming.webp` and set the Gaming category image (was NULL).
- `fill_product_images_from_categories.php` → updated 1 imageless product; a second run reported 0 updates (idempotent).
- Other category placeholders (`cpu`, `laptops`, `monitors`, `motherboard`, `ram`, `smartphones`, plus the older `case`, `cpu-cooler`, `monitor`, `peripherals`, `psu`, `ssd`) and the store/vendor placeholders were generated by running the scripts afterwards; those WebP files are present in the uploads folders.

### Generated files present

- `public/uploads/categories/placeholder-*.webp` (category placeholders)
- `public/uploads/stores/placeholder-*.webp` (6 store logos)
- `public/uploads/vendors/placeholder-*.webp` (vendor placeholders)

### Caveats

- These scripts are **one-time DB updates**, not runtime fallbacks. New products/categories/stores/vendors added later need the relevant script re-run (or a manual dashboard upload).
- Never overwrite behaviour is intentional: script output reports `already has an image/logo` and skips.
- `vendors.image` is not yet used by the vendor create/edit forms or the public seller card; displaying it needs a follow-up task.
- Store logos are only visible in the dashboard (no public store pages).
- Public image paths are stored with a leading slash (e.g. `/uploads/categories/placeholder-gaming.webp`) and views prepend `$base`.
